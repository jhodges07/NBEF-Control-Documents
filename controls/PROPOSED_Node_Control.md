## 1. Purpose and scope

This proposed CONTROL’s bounded purpose is to govern the canonical **NBEF Node** concept: identity, recognition, composition, and authorized lifecycle and operational-state rules.

If adopted, this CONTROL would be the authoritative home for the Node subjects it states, under CONTROL 00 one-authoritative-home discipline. The NBEF Node concept is expected as a foundational subordinate CONTROL subject. That expectation does not designate CONTROL 01.

This proposed CONTROL SHALL treat as canonical Node subjects at least: recognition/entry; modification; suspension; restoration/reactivation; termination; replacement.

This proposed CONTROL SHALL NOT:

- define the complete education architecture;
- become a catch-all architecture CONTROL;
- define Signal, parent authority/rights substance, governance/local-control architecture, measurement/performance/accountability systems, funding architecture, external interfaces, Community Schools, or curriculum/pedagogy.

Detailed doctrine belonging in later CONTROLs remains in those later CONTROLs.

This proposed CONTROL does not implement software or an operational state machine.

**Source:** CONTROL 00 §§3, 4, 7, 16; CWC #7 Decision 1-B, Decision 4-A and follow-up YES; CWC #8 N3-A, N11-A, N14-B, N15-B, N16-C, N17-A, N18-A, N19-A; CWC #9 L1 / §6.13; CWC-CE #11 purpose.

## 2. Node identity

The canonical term is **NBEF Node**.

An NBEF Node is a distinct unit of education that NBEF recognizes as one bounded subject of the framework.

NBEF requires its own independently defined Node concept.

NBEF Node meaning is **not** NBBF Node meaning. NBBF terminology, including Node, SHALL NOT automatically acquire NBEF meaning.

Similarity to another framework is not authority.

**Source:** CWC #7 Decision 4-A; CONTROL 00 §§2, 8, 10; CWC #8 N1-A, N2-A, statement 12.

---

## 3. Node purpose and boundary

A Node exists to identify the units to which NBEF architecture applies.

What makes something one Node rather than part of another is distinct NBEF recognition as one unit.

Minimum independence presently required is distinct recognizability as one NBEF unit. No further independence is defined here.

Valid recognition requires:

- a distinct educational unit;
- distinct recognizability; and
- a bounded identity distinct from other recognized Nodes.

**Source:** CWC #8 N3-A, N4-A, N7-A; CWC #9 R2-A.

---

## 4. Possible Node population

The following kinds of things **MAY** qualify as NBEF Nodes:

- school;
- classroom;
- program;
- learning organization;
- administrative body;
- community institution;
- service provider.

Those classes are possibilities. They are **not** automatic Nodes. This list is **not** declared exclusive.

Recognition remains required. An entity in a listed class is not an NBEF Node unless recognized under Section 5.

**Source:** CWC #8 N5; CWC #9 R3-A, R4-A.

## 5. Recognition

Until a later CONTROL separately authorizes another recognition process, the Human Engineer through a controlled CWC MAY confer NBEF Node recognition.

This proposed CONTROL does not create or authorize a school office, board, agency, administrator, or automated recognizer. Any later recognizer other than the Human Engineer through a CWC belongs to a later CONTROL, not to invented offices.

Recognition is a declarative explicit NBEF act that an entity is a recognized NBEF Node.

A candidate or proposed Node MAY exist. Candidacy is **not** NBEF Node recognition.

Two recognized Nodes SHALL NOT be the same bounded unit. Unresolved overlap blocks recognition until the recognizer under this section resolves it.

Recognition SHALL be recorded in this NBEF control-document repository through the authorized CWC/CONTROL process.

**Source:** CWC #9 R1-A, R2-A, R3-A, R4-A, R5-A, R6-A, §8; CWC #8 N10-A.

---

## 6. Composition

Nodes MAY contain subordinate Nodes.

A parent/subordinate relationship is established by explicit NBEF composition recognition, using the same recognizer class as Section 5.

A subordinate Node remains independently recognizable as one NBEF Node.

A Node has at most one parent Node.

Nesting is permitted: subordinate Nodes MAY contain subordinate Nodes.

Composition SHALL NOT by itself create authority, governance, Signal, or accountability inheritance.

Removal from a parent changes composition only. It does not by itself terminate the subordinate Node.

**Source:** CWC #8 N6-A; CWC #9 C1-A, C2-A, C3-A, C4-A, C5-A, C6-A.

---

## 7. Activation

Activation is an operational state of an already recognized Node. It is not a new Node identity.

Recognition is a prerequisite. A Node cannot be active unless it is recognized.

A recognized Node need not ever become active.

Who MAY activate a Node: the same recognizer class as Section 5.

Activation is a declarative explicit NBEF act, recorded like recognition.

**Source:** CWC #9 L2-B; CWC #10 A1-A, A2-A, A3-A, A4-A, A5-A.

---

## 8. Minimum operational distinctions

NBEF requires these minimum operational distinctions:

- recognized-not-active;
- active;
- suspended;
- terminated.

Terminated means recognition has ended (Section 12).

This section is not a software implementation and does not invent an expanded state machine.

**Source:** CWC #10 OS1-A; CWC #9 L4-A.

---

## 9. Suspension

Suspension does not end recognition.

A suspended Node is not active while suspended.

Who MAY suspend a Node, and what record is required: the same recognizer class as Section 5; the act SHALL be recorded in this repository through the CWC/CONTROL process.

Suspension does not expire by itself. Restoration/reactivation is a separate act (Section 10).

**Source:** CWC #10 S1-A, S2-A, S3-A; CWC #9 L1.

---

## 10. Restoration / reactivation

Restoration and reactivation are the same lifecycle act.

That act requires current recognition that has not been terminated.

Prior identity is preserved. No new recognition act is required.

After that act, the Node is active.

**Source:** CWC #10 RR1-A, RR2-A, RR3-A; CWC #9 L1.

---

## 11. Modification

Modification SHALL NOT by itself create a new Node.

Identity continues unless recognition is withdrawn or superseded.

**Source:** CWC #9 L3-A.

---

## 12. Termination

Termination ends NBEF Node recognition for that unit.

Who MAY terminate, record, and effective point: the same recognizer class as Section 5; the act SHALL be recorded in this repository; it is effective when that authorized act is recorded.

The historical record of the terminated Node SHALL persist. Historical existence is not current recognition.

A terminated Node cannot be restored. Any later Node requires a new recognition act, not restoration.

**Source:** CWC #9 L4-A; CWC #10 T1-A, T2-A, T3-A.

---

## 13. Replacement

Replacement recognizes a different Node.

Replacement is not modification of the same Node.

The prior Node’s recognition ends by termination **or** as part of the authorized replacement act.

That disjunction is preserved. This proposed CONTROL does not choose between those alternatives.

**Source:** CWC #10 RP1-A; CWC #9 L1, L3-A, L5-B.

## 18. Composition / lifecycle interaction

Parent termination does not by itself terminate subordinate Nodes.

Parent replacement does not by itself terminate subordinate Nodes.

Moving a Node between parents is composition change only.

**Source:** CWC #10 CL1-A; CWC #9 C6-A.

---

## 19. Authority and accountability at a Node — reserved substance

A Node MAY hold NBEF-recognized educational authority. The substance of that authority belongs to later parent-authority and/or governance CONTROLs.

Accountable outcomes MAY attach to a Node. The substance belongs to the later measurement/accountability CONTROL.

**Source:** CWC #8 N8-A, N9-A.

---

## 20. Reserved later-CONTROL boundaries

This proposed CONTROL does not define substantive doctrine for:

- parent authority/rights (constrains Nodes; is not Node identity);
- governance/local control (later CONTROL; Node identity is not a governance system);
- Signal (relationship deferred to future Signal definition; composition does not inherit Signal);
- measurement/performance/accountability (participation deferred; composition does not inherit accountability);
- funding (Node identity is not defined by funding arrangements);
- external interfaces (no Node interface boundary now; later dedicated interface CONTROL);
- Community Schools (an implementation using Nodes; later dedicated CONTROL home; not defined here);
- curriculum/pedagogy (Node architecture SHALL NOT centralize curriculum or pedagogy).

Organic Community Schools remains the predecessor name for Community Schools.

**Source:** CWC #7 Decisions 2-B, 3-B, 5-A, 6-A, 7-A, 8-B, 9-A, 10-B, 13-B; CWC #8 N12-A, N13-A, N14-B, N15-B, N16-C, N17-A, N18-A, N19-A; CWC #9 C5-A.
