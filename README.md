# Node-Based Education Framework (NBEF)

This repository is the control-document home of the **Node-Based Education Framework (NBEF)**.

NBEF is a separate authoritative domain framework. **NBEF is not NBBF.**

## Repository purpose

`NBEF-Control-Documents` holds the canonical NBEF control documents and the CWC-controlled work required to establish, review, and maintain them.

This repository does not implement software, Digital Twin systems, Runtime Republic systems, APIs, or education operations. It records NBEF control authority in documents.

## Human Engineer authority

The Human Engineer is the sole authority to:

- create, adopt, amend, or withdraw NBEF CONTROL documents
- designate source material as canonical, referenced, non-canonical, or out of scope
- resolve unresolved authority
- authorize GitHub remotes, visibility, ownership, and push

No agent may invent NBEF architecture, silently create CONTROL authority, or treat a gap in the record as permission to fill it.

## Agent identity

The repository-bound agent role for this workspace is **NBEF — Control Steward**.

The Control Steward may not:

- invent NBEF architecture or education doctrine
- silently create CONTROL authority
- copy the NBBF CONTROL tree into this repository
- modify NBBF, UNBKE, Runtime Republic, or any other repository
- treat historical drafts, essays, conversations, podcast material, or advocacy writing as canonical authority without Human Engineer review

## Canonical-document intention

Canonical NBEF control documents SHALL be written in **Markdown (`.md`)**.

Numbered CONTROL documents exist only when the Human Engineer authorizes them through a CWC. **CONTROL 00 has not been created.**

## Version-control intention

NBEF control documents SHALL be versioned with **Git**.

A GitHub remote may be added later only when the Human Engineer authorizes ownership, visibility, and repository settings. A local Git repository is sufficient until that authorization exists. Do not push unless the Human Engineer explicitly instructs it.

## CWC-controlled development

Work in this repository SHALL proceed by Controlled Work Cycle (CWC).

A CWC may create only what it is authorized to create. Later CWCs SHALL NOT be auto-started.

## Fail-closed unresolved authority

If authority, source status, scope, or adoption status is unresolved, the Control Steward SHALL stop and return the question to the Human Engineer.

Do not invent architecture, doctrine, formulas, rights frameworks, governance rules, or CONTROL text to close a gap.

## Independence from NBBF

NBBF may later provide referenced governmental budgeting, accountability, Signal, review, transparency, and structural principles **where explicitly adopted by NBEF**.

NBEF SHALL remain a separate authoritative domain framework.

The following are prohibited:

- silently importing NBBF doctrine
- copying the NBBF CONTROL tree into this repository
- treating NBBF CONTROLs as NBEF CONTROLs
- making NBEF subordinate in a way that destroys separate repository authority

## Non-canonical material

Historical drafts, essays, conversations, podcast material, advocacy writing, and similar sources are **not** canonical NBEF authority unless and until the Human Engineer reviews and adopts them.

## Repository layout

- `controls/` — future location of Human Engineer–authorized NBEF CONTROL documents
- `Audit/` — future location of repository audit records for NBEF control-document work
- `.cursor/rules/` — repository-local Cursor rule binding this workspace to **NBEF — Control Steward**
